# FormKit native invalidation checkpoint and correction (2026-11-05)

The performance experiment below tested executable source `83f236c6d8074769a1e950799fc30cd65db01d5c` (source-tree SHA-256 `5cbbff1464a249612c9fae073b117ee2ef10e28c05555ea0338c1ea5956531b3`) against baseline `85f6e5389c8c0734087b62e9273c4288892e1cc3`. Its native bundle SHA-256 was `e58fb880a2883d04c21a11a8d18b3d8e61d0faed1b35e3f9c29f0c6006a9e929`. **That experiment is historical and rejected as acceptance evidence:** the published documentation head `720ac74d869f76ba97c0dfb12bc67a3821b77e49` retained a root invalidation error. The current repaired executable source is `f8db8c0c8d8e1bd3e5139e9a277900e7ac99c7b1` on `codex/formkit-master-integration-20261103`. Its independently reported replay is summarized below. This note is not a release or parity claim.

Native projections reuse an input render only when captured context, configuration inheritance, ownership, slots, attributes and pending work are proven independent of the update. Root count notifications remain public. The original flat-schema proof omitted retained `submitAttrs`: a later unrelated child update could leave the default submit button's `title` or help text stale. The repair certifies only an adapter-created default submit-props object by identity and checks its scalar contents on reuse; supplied objects, Proxies, accessors, functions and nested values use full reconciliation. Dynamic schemas, custom getters/hooks and uncertain ownership also retain the full path. An ignored submit control retains the form's configuration after Core detaches its value parent; its original configuration ancestry is included in that proof.

Historical gates for the rejected experiment: 2,820 tests passed plus one expected failure under unchanged canonical coverage thresholds; build, lint, API inventory, public-test boundary, packed ESM/CommonJS consumer and declaration checks passed; 19 Chromium journeys passed. Its first coverage run timed out in five existing row/lifecycle cases. Both affected files then passed 43/43 in isolation, and the unchanged full replay passed; the first timeout's cause remains unresolved. Those green gates did not detect the retained submit-props counterexample.

Repair proof on the same public test oracles: the retained `title` attribute and submit help text both update on `85f6e538`, both remain stale on `720ac74d`, and both update on `f8db8c0c`. The first is triggered by a child context update; the second by a child `label` prop update. An application-owned submit-props Proxy also failed during repair development and now takes the full path. Direct mutation of the publicly reachable default object, nested values and accessors have focused preservation tests. On repaired source, 529/529 FormKit package tests, canonical coverage (2,827 passed plus one expected failure at unchanged thresholds), build, lint, API/public-test checks, packed ESM/CommonJS/declaration consumer and 19 sandbox-enabled Chromium journeys passed. Independent read-only source review cleared the repair.

Independent cloud QA subsequently replayed packed executable source `f8db8c0c8d8e1bd3e5139e9a277900e7ac99c7b1`. It reported four retained submit-props cases passing on baseline and repair, and all four failing on rejected `720ac74d`; the strong 200-field message/ARIA/edit/reset oracle, real-keyboard mixed-form journey (8/8 per adapter), and 158/158 established native Pro checks passed.
