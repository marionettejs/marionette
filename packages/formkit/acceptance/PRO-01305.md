# Pro 0.130.5 compatibility — historical checks

The optional consumer fixture was updated to Pro 0.130.5 on November 6, 2026,
using executable adapter source `e3a4c196` and Core-family packages 2.1.2. Pro
remained a consumer plugin, not an adapter runtime dependency. These results do
not certify the fixture's currently selected Pro version.

The [official notes](https://github.com/formkit/docs-content/blob/master/_changelog-pro/138.v0.130.5.md)
identify autocomplete new-value commits on blur, popover positioning, and
year-at-a-time month-panel navigation. The `release-01305` scenario retains
these controls. Its ordinary custom-definition unit test checks declared props
and explicit updates; it does not simulate or certify actual Pro behavior.

Writer checks passed with Node 24.19.0/npm 11.17.0: repository build/types,
539 public FormKit cases, lint, contracts, package checks, packed consumers and
documentation checks. Three isolated consumers passed installation, locked
reinstallation, imports, declarations and production builds. They resolved
Core-family 2.1.2, drag-and-drop 0.6.3 and Tempo 1.1.0; native/React installed no
Vue packages. Independently reported QA passed the same eight gates using
Node 24.19.0/npm 11.9.0. That npm difference remains explicit.

Two separately reported actual-Pro studies had different scopes:

- An earlier four-arm comparison found the static colorpicker `above` placement
  failure across both native variants, Vue and React. Its old-regression
  collector passed 8/8 per arm. New checks were 22/23 on each native variant and
  21/23 on the references, with focus/ARIA expectations classified separately.
- The final scenario study ran the native old-regression collector unchanged:
  8/8 passed. New checks pooled native and selected Vue controls into **19
  logical groups: nine passed and ten placement groups failed**. These are not
  19 cases per adapter. React was not repeated in that final study.

Autocomplete novel/exact-label/retained-selection blur, Escape/reset,
month-panel year navigation, date selection, submission and teardown passed in
their tested scope. Updating `auto` to `above` while open did not reposition any
of the five popup types. Reopening honored `above` for autocomplete, dropdown,
taglist and datepicker; colorpicker stayed below. Native/Vue behavior matched.
Recognized props and successful builds were not counted as correct geometry.

Those placement outcomes remain failures. An initial `March` selector was
corrected to the rendered `Mar`; its failed outcome was retained separately.
The writer did not execute these browser studies; their results are attributed
to independent QA. They establish neither complete feature success nor a
performance improvement.
