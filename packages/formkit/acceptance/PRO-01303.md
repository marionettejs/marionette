# Pro 0.130.3 release assessment — 2026-11-03

This assessment accompanies the master-based integration branch. It does not
replace the earlier versioned 0.130.1/0.130.2 receipts or extend their results to
new source or Pro versions. Adapter production code is unchanged by this update.

## Verified package delta

Official registry metadata reports 0.130.3 published at **14:28:25.746 UTC** on
November 3. Both official archives were downloaded and matched against their
registry SHA-512 integrities; exact metadata and file hashes are in
[pro-01303/](pro-01303/).

Only `index.mjs`, `index.cjs` and the package version changed among 35 files. Each
root bundle grew 463 bytes. Dependencies, peer dependencies, exports, declarations,
README, CSS, license and control-subdirectory files are unchanged. No package
changelog was added. The public changelog view retrieved for this assessment did
not expose a 0.130.3 entry, and the registry git-head comparison returned 404 on
public GitHub; no separate upstream release-note claims are asserted here.

Independent static review of the bundles identified two changes:

- Active-option scrolling avoids pointer-hover tracking and repeated scrolling to
  the same active descendant. Per-node tracking resets on close.
- Open popovers observe height changes and refresh positioning/inversion when the
  height differs. Observers disconnect on close/destruction and resume on reopen.
  The shared feature serves dropdown, autocomplete, datepicker, taglist and colorpicker.

The root ESM/CJS imports remain FormKit utils/core/inputs, drag-and-drop and tempo.
Neither version has the earlier undeclared Vue import. At clean source
`605f1f1aaccb63f9195f15e26f64e8f1d00f409c`, a fresh native consumer and locked
reinstall contained no Vue packages; direct Node ESM/CommonJS imports and the
Vite build passed. The native comparison passed 14/14 core assertions with no
page/runtime errors. Its collector correctly exited 1 for keyless Pro bootstrap;
no actual Pro controls were rendered. See the [versioned integration receipt](master-integration-20261103/README.md).
No adapter change is justified by the static delta alone.

## Verification boundary

The isolated fixture now pins Pro **0.130.3** while retaining Core **2.1.2** and
its independent native/Vue/React installation paths. Existing source, package and
native browser results remain attributed to their recorded revisions. Independent
vault QA reported 107/107 functional assertions at `db655482`, but the original
fixture passed only 12/30 extended positioning checks. A transient
`.formkit-inner { position: relative; }` rule passed 30/30. Exact installed package
inspection confirms base Genesis provides that unconditional rule; Pro Genesis
is an extension. The shared fixture now imports base Genesis first and declares
Themes 2.1.2 explicitly for all three consumers. The collector has a permanent
computed-position/containing-block check, reproduced failing before correction.
This is a fixture theme correction, not an adapter runtime styling patch.

The updated runtime and permanent theme setup require their own actual-control
retest in the separate authorized vault QA environment; this writer
environment has no `FORMKIT` binding. No new key, account, authorization endpoint,
license bypass or customer-source copy is required or attempted.

Use the [fixture instructions](../../../test/fixtures/formkit-pro/README.md) for
bounded overflow navigation, panel resizing, close/reopen and teardown checks.
Do not interpret a dependency build, keyless bootstrap result or historical
107/107 Pro 0.130.2 result as current Pro 0.130.3 acceptance.
