framework timing comparison. The new ordinary-definition unit test validates
prop/slot forwarding and explicit updates; it does not simulate Pro calendars.

## Independent baseline, Core 2.1.2

These are independently reported results on unchanged native source, not writer
browser trials or exact acceptance of this review revision:

- Ordinary inline without authored `popover` is below the input and preserves
  initial focus. The explicit inline+popover combination is at page top in all
  three adapters and may obstruct pointer submission. Normal Tab progression
  was observed separately.
- Real inline day-segment edits followed by Tab leave the model at November 9
  in all three adapters. Native/React display November 12; Vue displays November
  20, a separate display-assertion failure. Old/new native popup positive
  controls commit November 12. Keep both model and display assertions strict.
- Sequence restart and visibility pass, but keyboard month-to-day selection
  loses focus to BODY in all three. A visibility pass does not erase that focus
  failure. Dynamic author-prop transitions remain uncertified.
- Current custom-wrapper counts are one, but the old native control also has
  one in this setup. The historical duplicate bug was not reproduced.
- Baseline lifecycle checks passed 113/113 per native version, with five real
  intervals, zero forced clears and live survivors. The common collector passed
  8/8. Neither count is a new result for this review revision.

Initial missing-calendar and callback-slot inferences were withdrawn after
correcting invalid fixture protocols: FormView.el requires an HTMLFormElement,
and callback slots use `slots` rather than named child schemas. No native-only
defect or runtime repair is established by those protocols. Shared typing,
