# Pro 0.130.7 lifecycle compatibility — historical checks

The optional fixture was updated to Pro 0.130.7 on November 8, 2026. Executable
adapter source remained `e3a4c196`, with Core-family packages 2.1.2. No adapter
runtime change or performance experiment was adopted. Pro remains optional.

The [0.130.7 notes](https://github.com/formkit/docs-content/blob/master/_changelog-pro/140.v0.130.7.md)
and [issue 1817](https://github.com/formkit/formkit/issues/1817) describe clearing
the Pro plugin's interval on destruction. The preceding
[0.130.6 notes](https://github.com/formkit/docs-content/blob/master/_changelog-pro/139.v0.130.6.md)
fix whole-day datepicker bounds. Published package integrity was verified;
dependencies, peers, exports, declarations and styles were unchanged between
0.130.6 and 0.130.7. Neither runtime format imports Vue.

The authored lifecycle helper installs its timer bridge before Pro import,
because Pro caches `setInterval`. It requires actual target-interval acquisition
for each form cohort and explicit Pro child, checks live survivors and disposed
callbacks separately, and snapshots before collector cleanup. It does not
assume one interval per native node. Eight synthetic unit controls discriminate
clean/leaking/indiscriminate cleanup, missing or unscoped acquisition, cached
aliases and recorder failure. These validate the helper, not Pro behavior.

Writer and independently reported checks passed build/types, 547/547 public
FormKit cases, lint, public boundaries, API contracts, package checks, packed
consumers and documentation checks. Three initial consumers passed installation,
locked reinstall, imports, declarations and production builds. Independent QA
prepared four arms: native 0.130.6/0.130.7, Vue 0.130.7 and React 0.130.7.
Core/reference adapters were 2.1.2, Tempo 1.1.1 and drag-and-drop 0.6.3. QA used
Node 24.19.0/npm 11.9.0; the writer used Node 24.19.0/npm 11.17.0.

Independent actual-Pro outcomes:

- The delivered lifecycle collector passed **113/113** on 0.130.7: five real
  intervals, zero active before cleanup and zero forced clears. Surviving
  owners' original handles kept ticking through child/transient teardown.
- Matched 0.130.6 acquired the same five intervals but retained all five with
  post-destruction ticks. Its 93 passes and 20 expected failures contain repeated
  cleanup assertions, not 20 distinct leaks. Both arms had zero page errors.
- The native common collector passed **8/8**. Keyboard date-bound checks passed
  **12/12 total** across min/max/both in the four arms. Native and Vue also
  completed submission, reset, invalid-email focus and registry/DOM teardown.

Two React follow-on interaction failures remain unexplained: a submit click
was intercepted by an open calendar, and a focused replay timed out waiting for
a subsequent calendar. A final targeted React control passed, but its popup was
already closed before Escape. That pass explains neither earlier failure and
does not erase them.

An earlier baseline at Tempo 1.1.0 observed 19 retained intervals on 0.130.6
versus zero on 0.130.7 after repeated remounts. Its separate listener study
remained stable. Those counts are not relabeled as the exact helper's five-
interval experiment at Tempo 1.1.1. Timer observations do not establish heap
collectability, listener cleanup or universal leak freedom.

Browser QA used Chromium 154.0.8037.57/Playwright 1.64.1 with explicit sandboxing;
this is not kernel attestation or broader device/browser coverage. Full canonical
coverage, online license validation, heap/GC and performance were not rerun.
Historical [0.130.5 placement limits](PRO-01305.md) remain; the original 158-check
helper is unavailable, so its replay is **0/158**. These versioned results do not
certify Pro 0.131.0 or the current review revision.
